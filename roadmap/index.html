Roadmap and status

Where ModelSaar is today, what the next step is, and what is planned but not implemented. Nothing in the "planned" list is available now.

Now: public alpha

  • Implemented and tested: OpenAI-compatible gateway (chat completions with streaming, models, embeddings, health), Ollama and generic OpenAI-compatible adapters, three-state capability evidence with probes and fingerprints, deterministic routing with profiles and aliases, session and tool-call continuity, admission control with memory budgets, decision records and a status page, the CLI, client configuration generators, an evaluation harness with sandboxed scoring, and a fault-injection test suite (285 tests at the built revision, including the independent reviewer's 29 contract checks kept verbatim; the 6 sandbox tests need an isolation backend and are skipped where none exists).
  • Exercised live: discovery, probes, routing, streaming, tool calls, tool-result continuity, session pinning and the measured-routing evaluation on an ASUS GX10: a three-model run against Ollama 0.32.13 (2026-10-11, historical) and, under one frozen contract at the current revision, runs with four models (Ollama 0.40.3, accepted), five and all eight installed generative models (Ollama 0.40.5) in October 2026 (Benchmarks).
  • Review status (precise): an independent review of the first public revision (1122e1f) produced 18 grouped findings, addressed on the hardening branch with regression tests (F01–F18). A second independent review of that branch (80276bb) reproduced 11 further contract failures and 6 launcher/installer observations (R1–R8; occupancy after stream/probe timeouts, resident-memory accounting, embedding identity anchoring, stream validation, the beginner path, evaluator isolation/scoring/resume, publication guards). Those were corrected on 2026-10-12 and the reviewer's own tests pass and are part of the suite; F04, F08, F10, F13, F14 and F17 were reopened and re-closed by that pass. A third independent review of the corrected revision (2026-10-12) reproduced five further edge conditions (failed residency query, refused-connection residency, stream terminal ordering, evaluator probe admission, checkpoint alternatives); they were closed in the alpha pass and the reviewer's tests are in the suite. Those three independent reviews covered 1122e1f, 80276bb and 5cb7443; the hardening was accepted and merged on 2026-10-13 (PR #1). Later changes — the website (PR #2), the isolated installer (PR #3), Odysseus session_id/cache_prompt compatibility (PR #4), the atomic environment switch (PR #5) and one-command upgrades (PR #6, merged 2026-10-14) — were verified by the project's own test suite and CI (including the installer cases against a real systemd user service on x86_64 and arm64) and by live checks on the owner's hardware, not by an independent reviewer. The installer pins cf56cdd, which the owner's GX10 runs.
  • Owner-reported: Odysseus chat through ModelSaar on the GX10 is working, reported by the owner on 2026-10-14. That is use reported in conversation, not a workflow recorded by the project; it does not cover tool, vision, streaming or agent workflows through Odysseus.
  • Preview (opt-in, experimental; not a release): decision-model support merged on 2026-10-28 — POST /v1/decisions and the classifier's mode: decision (Ollama's System One API: nimble, clef, laya). Fixture-tested in CI and exercised once live with three requests; try it from GitHub at one pinned commit, separately from a stable installation: Preview: decision models. The default installer pin is unchanged.
  • Not yet: a tagged release, a PyPI package or a container image (separate owner decisions); recorded real-client workflows for Open WebUI, OpenClaw, OpenCode and Hermes; a real vLLM/llama.cpp run; real-model embeddings; a reasoning-budget sensitivity run (prepared in the plan, not run); the macOS code-evaluation sandbox remains opt-in (MODELSAAR_MACOS_SANDBOX=verify; it was verified on the owner's Mac and used by the October 2026 evaluation runs).

Done since the alpha (2026-10-13 → 2026-10-14)

  • Hardening accepted and merged (PR #1); website and creator credits published (PR #2); this site is served from the gh-pages output branch with a recorded build identity.
  • One-line installer rebuilt for externally managed Python (PR #3), atomic environment switch with the previous environment retained (PR #5), and one-command upgrades that manage an existing Linux user service, verify the running revision and roll back a replacement that does not start (PR #6). The installer cases run in CI against a real systemd user unit on x86_64 and arm64.
  • Gateway-owned session_id / cache_prompt contract for llama.cpp-style clients (PR #4); the owner's GX10 was upgraded to cf56cdd with its configuration, keys and service preserved.
  • Website layout repair (command blocks, diagram) with rendered-layout checks at six widths, both themes, text enlargement and reflow.

Next

  1. Measured Routing Quality — completed in October 2026: Stage A (identity and capability baseline), Stage B (four-model accepted run, five-model cross-runtime run) and Stage C (all eight models) with separate calibration and held-out splits and fixed-model, rule, random and oracle baselines; evidence under docs/live-runs/ and a summary on Benchmarks. The plan's optional classifier comparison ran on 2026-10-25 with one configuration, which failed its predeclared timeout criteria and stays off — not a causal on-versus-off result (cross-runtime reference; same-session off twin compromised); see Benchmarks. Still open from the plan: a reasoning-budget sensitivity run (docs/plans/measured-routing-quality).
  2. One real client workflow recorded end to end by the project with its decision records (Odysseus is owner-reported working; Open WebUI is the quickest to record), then the others.
  3. A first tagged release (0.1.x) with a PyPI package and container image: the readiness list is in docs/release; tags and registry publication remain separate owner decisions.
  4. A run against a generic OpenAI-compatible server (vLLM or llama.cpp server) and real-model embeddings.

Planned, not implemented

  • Native decision-model adapters as routing classifiers and a decisions-style endpoint.
  • Audio and video inputs; multimodal embeddings; OCR and guardrail pipelines as separate results.
  • Responses API and Anthropic Messages with fail-closed translation.
  • Exact tokenisation for more runtimes; better served-context detection for Ollama.
  • Managed model lifecycle (keep-alive/unload) under leases and locks; composition with llama-swap.
  • Cascades and ensembles; scheduling across hosts.
  • Opt-in adaptive learning from outcomes with versioning, holdout evaluation, privacy controls and rollback.
  • Optional LLM-judge scorers in the evaluation harness, with identity, bias and cost disclosed.

The repository's roadmap file is the source for this list; the changelog records what actually landed, and the post-alpha backlog lists what the alpha deliberately leaves unverified or disabled (macOS code-execution sandbox, real-client walkthroughs, a live run under the current scorer).
