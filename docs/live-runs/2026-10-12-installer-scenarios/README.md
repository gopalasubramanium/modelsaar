# Installer scenarios — 2026-10-12 (cloud container, Linux x86_64, CPython 3.13)

`scripts/installer_scenarios.py` runs the real `site/static/install.sh` and the real CLI from this
checkout against loopback fixtures (the repository's fake backend as the inference server; a plain
HTTP service as the "unrelated listener"). Only the package-manager action is stubbed (`uv tool
install` is a no-op; the CLI runs from the checkout). Keys are generated by `modelsaar init` in a
temporary home and are redacted from the transcript.

| scenario | result | what it establishes |
|---|---|---|
| fresh install | PASS | `init` ran, a temporary gateway was started, `modelsaar test --model auto` printed ModelSaar attribution (`routed: 'auto' -> ollama/…`, request id), `verification: OK` |
| repeat install | PASS | existing config/keys kept byte-identical; check passes again |
| unrelated listener on the port (HTTP 200 on `/healthz`, plain text) | PASS | installer stops with "not a ModelSaar gateway"; the fixture saw exactly one `GET /healthz` without an `Authorization` header — **no key was sent** |
| `modelsaar test` against that listener | PASS | refuses before sending the key ("No key was sent", collision message) |
| `modelsaar serve` (first use after the installer) | PASS | gateway up; `/healthz` carries `service: modelsaar` |
| `modelsaar init` again | PASS (refuses) | exit 1 "already exists" — which is why the site no longer prints `modelsaar init && modelsaar serve` after the installer |
| `modelsaar test` | PASS | health identification, models, routed completion with request id |
| installer with the gateway running | PASS | identified by the health contract and reused; not restarted |
| `modelsaar client-config open-webui` | PASS | settings rendered from the running gateway (base URL with the configured port, model `auto`) |
| key command | PASS | `head -1 ~/.modelsaar/keys/api_keys` prints one `msk_…` line — the value to paste |

Not covered here (hardware/platform): macOS and the GX10 (`docs/live-runs/2026-10-11-installer/`
holds the earlier macOS uv transcripts at the previous revision); a real client UI (NOT RUN — see
`site/VALIDATION.md`).
