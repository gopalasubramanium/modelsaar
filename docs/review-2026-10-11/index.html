Independent review findings F01–F18

Rendered from docs/review-2026-10-11-findings.md at commit f18b2f195478. The repository file is authoritative.

The review grouped its confirmed findings under eight headings (privacy, dispatch contract, resources, embeddings, evidence, evaluator, first run/files, verification). This table keeps the reviewer's 18 grouped findings with stable ids, in the order the review stated them, and maps each to the implementation (branch hardening/review-2026-10-11), the regression test that asserts the corrected behaviour, and the evidence that it was executed.

Regression tests live in tests/test_hardening_2026_10_11.py (28 tests) unless noted. They assert the corrected behaviour. scripts/reproduce_review_baseline.sh is the diagnostic that runs the same tests against 1122e1f: 26 of 28 fail there — 22 on the behavioural assertion (the reviewed defect) and 4 because they use a config field or symbol the fix introduced (memory_margin_gb/unknown_memory_policy, identity, EVIDENCE_SCHEME; each has a sibling test that fails on the behavioural assertion). The two that pass are positive controls — replicas sharing an alias, evidence surviving load/unload — i.e. behaviour the fix had to preserve. The only adaptation needed to run them at the baseline is copying in the branch's fakebackend.py/conftest.py (new recorder and failure-mode hooks); the baseline's gateway code is untouched. Per-test outcomes with the failing assertion: docs/live-runs/2026-10-11-baseline/ (website branch).

Evidence keys: U = python -m pytest on the branch (see docs/verification-report.md for the exact revision and totals of each run); B = baseline reproduction above; L = live run on the GX10 (docs/live-runs/2026-10-11-gx10-hardening/); M = Mac test run (sandbox-exec; mac-tests-<commit>.txt, see verification report); CI = GitHub Actions on the PR revision — a CI definition exists for every item; a CI run is recorded here only once the branch has been pushed and the run has completed, which has not happened yet.
