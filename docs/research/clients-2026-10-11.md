### Configuration path / UI steps — Verified (starting-with-openai-compatible page)
1. **Settings > Admin > Connections > Manage OpenAI API Connections > Add Connection.**
2. Enter **URL** and **API Key**; the URL field autosuggests common endpoints.
3. If the provider has no `/models`, add model IDs to the **Model IDs** allowlist (type ID, click `+`).
4. **Save** (saving does not test). **Verify Connection** calls the provider's `/models` with a standard Bearer token and reports "Server connection verified."
5. Each connection has an enable/disable toggle, an **Advanced > Provider** dropdown (Default, Azure OpenAI, llama.cpp, LM Studio, LiteLLM — "Default is always safe"), **Advanced > Forward cookies** (off by default), and a `prefix_id` option (source: `routers/openai.py`).

### Base URL and `/v1` — Verified (routers/openai.py + provider page)
- Paths are **string-concatenated onto the configured URL**: `request_url = f'{url}/chat/completions'`, `f'{url}/models'`, `f'{url}/responses'`, `f'{url}/embeddings'`. No trailing-slash strip on the generic path (a trailing `/` yields `//`).
- Therefore the connection URL **must include `/v1`** for ModelSaar: `http://127.0.0.1:8484/v1`. Docs examples confirm (`http://localhost:10000/v1` for llama.cpp; Bedrock Access Gateway uses `/api/v1`; Azure legacy has no path). The provider page says "the exact path matters" and the management API strips a trailing `/v1`, `/api/v1`, `/api/v0` for its own model-management calls only.
- Open WebUI uses `/models` (not `/v1/models` literally) relative to the configured URL — so ModelSaar must answer `GET /v1/models`.

### API key — Verified
- UI field **API Key** / env `OPENAI_API_KEYS`. Sent as `Authorization: Bearer <key>` for `auth_type` bearer/unset; `none` sends no token. Leave blank for keyless local servers. Custom headers (`custom_headers`) are merged last and can override `Authorization`.

### Model listing / metadata — Verified
- **Auto-lists** from `GET {url}/models` per connection (`get_models_request`), cached per user (`MODELS_CACHE_TTL`); or static `model_ids` allowlist when `/models` is unsupported. Duplicates across connections: first occurrence wins; `urlIdx` recorded. `prefix_id` is prepended as `f'{prefix_id}.{id}'` and stripped before forwarding.
- **No model metadata schema** (context window, tool flags, vision, cost) is read from `/models`; capabilities are configured per model in Admin > Models (Advanced Params, Function Calling mode, capabilities toggles). Not documented as derived from upstream metadata.

### API protocol — Verified
- **Default: OpenAI Chat Completions** (`/chat/completions`). A Responses path exists in the router (`f'{url}/responses'` via `convert_to_responses_payload`) and an Anthropic token-count path, but the default/generic OpenAI-compatible connection uses Chat Completions. The per-connection **Provider** dropdown selects Default/Azure/llama.cpp/LM Studio/LiteLLM extras, not a protocol switch to Responses (not documented as such on fetched pages). `ENABLE_OPENAI_API_PASSTHROUGH` (default False) gates a catch-all proxy.

### Tool calling — Verified (tools.md + middleware.py)
- **Native (Agentic) mode is now the default**; the old prompt-injection mode was renamed **Legacy** and is "no longer supported". Configured per model (Admin > Models > Advanced Params > Function Calling), globally via Model Defaults / `DEFAULT_MODEL_PARAMS.function_calling`, or per chat (Chat Controls).
- Native mode sends `form_data['tools'] = [{'type': 'function', 'function': tool.get('spec', {})} ...]` plus inlet-filter tools. **No `tool_choice` and no `parallel_tool_calls` assignment found** in the fetched middleware/openai router code.
- Streaming: Open WebUI streams chat completions; the streaming tool-call-delta accumulator was in the unfetched tail of `middleware.py` — **Unverified whether it relies on `delta.tool_calls` streaming deltas** (expected, but not confirmed from the excerpt). Strict JSON schema: not referenced.
- Docs warn small local models (<~30B) often produce malformed tool JSON; recommend a stronger model rather than Legacy.

### Session / conversation identifiers — Verified (routers/openai.py, env.py, headers.py, tasks.py)
- **Body:** `metadata = payload.pop('metadata', None)` — the internal `metadata` dict (which holds `chat_id`, `message_id`, `session_id`, `user_id`, `task`, `task_body`, etc.) is **removed** before the upstream call. No top-level `user`, `chat_id`, `session_id`, or `prompt_cache_key` is added by Open WebUI on the generic path (client-supplied `user` passes through; pipelines get a `user` object). So by default **no conversation identifier reaches the gateway in the body**.
- **Headers (opt-in):** when `ENABLE_FORWARD_USER_INFO_HEADERS=true` and a user is present, Open WebUI sends
  - `X-OpenWebUI-User-Name`, `X-OpenWebUI-User-Id`, `X-OpenWebUI-User-Email`, `X-OpenWebUI-User-Role` (legacy set; replaced by a single `X-OpenWebUI-User-Jwt` if `FORWARD_USER_INFO_HEADER_JWT_SECRET` is set), `X-OpenWebUI-Auth-Type`,
  - **`X-OpenWebUI-Chat-Id`** — `headers[FORWARD_SESSION_INFO_HEADER_CHAT_ID] = metadata.get('chat_id')` inside the same `ENABLE_FORWARD_USER_INFO_HEADERS and user` block, only when `metadata.chat_id` is present. Header name overridable via `FORWARD_SESSION_INFO_HEADER_CHAT_ID`. A `FORWARD_SESSION_INFO_HEADER_MESSAGE_ID` (`X-OpenWebUI-Message-Id`) constant exists in env.py but is **not referenced in routers/openai.py**.
  - All header names overridable via `FORWARD_USER_INFO_HEADER_*` env vars.
- **Custom headers** per connection support templates `{{CHAT_ID}}`, `{{MESSAGE_ID}}`, `{{USER_MESSAGE_ID}}`, `{{TASK}}`, `{{USER_ID}}`, `{{USER_NAME}}`, `{{USER_EMAIL}}`, `{{USER_ROLE}}`, `{{USER_GROUPS}}`, `{{USER_AGENT}}`, `{{AUTH_TYPE}}`, etc. — so an admin can send e.g. `X-Session-Id: {{CHAT_ID}}` to ModelSaar without enabling user-info forwarding.
- **Implication for ModelSaar affinity:** read `X-OpenWebUI-Chat-Id` (and `{{TASK}}` via custom header to detect task-model calls); fall back to hashing the first user message when absent.

### Task model (title, tags, follow-ups, queries, autocomplete, emoji, image prompt) — Verified (tasks.py, task.py)
- Every task endpoint except MOA builds a **non-streaming** request (`"stream": False`) with `metadata = {...request.state.metadata, 'task': str(TASKS.X), 'task_body': form_data, 'chat_id': form_data.get('chat_id')}`. Title generation defaults `max_tokens` to the model's `info.params.max_tokens` or 1000; emoji forces `max_tokens: 4`.
- Model choice (`get_task_model_id`): start with the current chat model; if that model's `connection_type == 'local'` use `TASK_MODEL` (if set and present), **else use `TASK_MODEL_EXTERNAL`** (if set and present); otherwise fall back to the current chat model. For ModelSaar connections (`connection_type` external) set `TASK_MODEL_EXTERNAL` (e.g. `auto-fast`), or these small requests hit whatever model the user is chatting with (including `auto-quality`).
- Because `metadata` is popped before upstream, the **`task` marker is not visible to the gateway** unless forwarded via a custom header `{{TASK}}`. Dedicated task-model docs page: Unverified (fetch error).

### Container networking — Verified (quick-start)
- Quick-start `docker run` includes `--add-host=host.docker.internal:host-gateway` ("Lets the container reach Ollama, or anything else, running on your machine"). Compose: `extra_hosts` "makes `host.docker.internal` resolve to the host on Linux". Default Ollama probe is `http://host.docker.internal:11434`. Podman: use `http://host.containers.internal:11434` (`host.docker.internal` "does not resolve"). The provider page: "If the model server runs on the host, replace `localhost` with `host.docker.internal` in the URL." Host service must listen on `0.0.0.0` (or at least the docker bridge) — docs say this for Ollama. `--network=host` is not mentioned on the quick-start page.
- ModelSaar URL from Dockerised Open WebUI: `http://host.docker.internal:8484/v1`; on Linux add `--add-host=host.docker.internal:host-gateway` and bind ModelSaar to a non-loopback address.

### Documented pitfalls — Verified (provider page)
- Gemini URL must be exactly `.../v1beta/openai` with no trailing slash or `/models` breaks — same class of issue applies to any URL: path is concatenated verbatim.
- Providers without `/models` need manual Model IDs. Model-list timeout 10 s (`AIOHTTP_CLIENT_TIMEOUT_MODEL_LIST`). Large catalogs: use allowlist + `ENABLE_BASE_MODELS_CACHE=True`.
- Forward-cookies: never enable for untrusted upstreams (sends the Open WebUI session cookie).
- Azure auto-detected from `azure.`/`cognitive.microsoft.com` in URL.

### Config file — Verified (gateway/configuration)
- `~/.openclaw/openclaw.json`, **JSON5** (comments allowed), optional (safe defaults if missing). Override path with `OPENCLAW_CONFIG_PATH`; must be a regular file, not a symlink.
- Agent-level override: `~/.openclaw/agents/<agentId>/agent/models.json`; `OPENCLAW_AGENT_DIR` overrides the agent root.
- `models.mode`: `"merge"` (default) or `"replace"`.

### Provider schema (`models.providers.<id>`) — Verified (custom-providers)
| Key | Notes |
|---|---|
| `baseUrl` | Upstream base URL. Example `http://localhost:4000/v1` — **`/v1` is included**. Configuring a custom `baseUrl` trusts that exact `scheme://host:port` origin for model HTTP requests. |
| `apiKey` | Credential; SecretRef or env substitution preferred. Examples: `"LITELLM_KEY"` (env var name marker), `"${LM_API_TOKEN}"`, literal `"llamacpp-no-key"`. Local servers without auth "accept any placeholder value". |
| `api` | Request adapter. Values: `openai-completions`, `openai-responses`, `openai-chatgpt-responses`, `anthropic-messages`, `google-generative-ai`, `google-vertex`, `github-copilot`, `bedrock-converse-stream`, `ollama`, `pi-messages`, `azure-openai-responses`. **A provider with `baseUrl` but no `api` defaults to `openai-completions`.** "Use `openai-responses` only if the backend supports `/v1/responses`. For MLX, vLLM, SGLang, and most OpenAI-compatible local servers, use `openai-completions`." |
| `auth` | `api-key`, `token`, `oauth`, `aws-sdk` |
| `authHeader` | `true` forces credential into `Authorization` |
| `headers` | static extra headers |
| `maxTokens` | default output cap for the provider's models |
| `timeoutSeconds` | per-provider HTTP timeout |
| `injectNumCtxForOpenAICompat` | Ollama + openai-completions: inject `options.num_ctx` (default true) |
| `request` | `headers`, `auth` (`provider-default` / `authorization-bearer` / `header`), `proxy`, `tls`, `allowPrivateNetwork` (default false; set true for RFC1918/CGNAT ranges) |

### Model declaration (`models.providers.<id>.models[]`) — Verified
`id` (sent to backend), `name`, `reasoning` (bool), `input` (`["text"]` or `["text","image"]`; images only attached if marked image-capable), `cost` `{input, output, cacheRead, cacheWrite}`, `contextWindow`, `contextTokens` (active-input cap, optional), `maxTokens`. Per-model `compat` block (provider-examples / custom-providers): `supportsTools`, `toolSchemaProfile` (e.g. `"llamacpp"` strips `pattern`/`maxLength` ≥ 2000), `unsupportedToolSchemaKeywords` (list), `supportsDeveloperRole` (forced `false` on non-native endpoints), `supportsReasoningEffort`, `supportsPromptCacheKey`, `supportsLongCacheRetention`, `supportsUsageInStreaming` (seen in table header), `codeMode`. Docs: "a `compat` block ... should only declare capabilities verified against that endpoint"; `openclaw doctor --fix` removes redundant overrides.

### Model discovery — Verified
Generic custom providers are **not auto-listed from `/v1/models`**: "For custom provider models, also add `models.providers.<provider>.models[]` with at least the matching `id`". Discovery exists only for bundled providers (LM Studio native `/api/v1/models`; vLLM/SGLang opt-in via `VLLM_API_KEY`/`SGLANG_API_KEY` env then "use IDs returned by `/v1/models`"; Ollama via `OLLAMA_API_KEY`). In merge mode declared entries do not restrict discovery; restrict with `agents.defaults.modelPolicy.allow` (exact refs or `provider/*`; introduced v2026.8.1) or `models.mode: "replace"`.

### Default model / alias — Verified (concepts/models + custom-providers example)
- Model ref format `provider/model`. Primary: `agents.defaults.model.primary` (or `agents.defaults.model` as a string); `agents.defaults.model.fallbacks` tried in order; per-agent `agents.entries.*.model` overrides. Aliases live in `agents.defaults.models."provider/model".alias` (example: `models: { "lmstudio/my-local-model": { alias: "Local" } }`). `/model` in chat pins a strict session override (`/model default` clears). Also `utilityModel` (cheap internal tasks; defaults to a provider small model else primary), `decisionModel`, `imageModel`, `pdfModel`, `mediaModels`.

Example for ModelSaar (fields verified above; adapted from the docs' LM Studio/LiteLLM examples):
```json5
// ~/.openclaw/openclaw.json
{
  agents: {
    defaults: {
      model: { primary: "modelsaar/auto", fallbacks: ["modelsaar/auto-fast"] },
      models: { "modelsaar/auto": { alias: "Auto" }, "modelsaar/auto-code": { alias: "Code" } },
    },
  },
  models: {
    mode: "merge",
    providers: {
      modelsaar: {
        baseUrl: "http://127.0.0.1:8484/v1",
        apiKey: "${MODELSAAR_API_KEY}",
        api: "openai-completions",
        timeoutSeconds: 300,
        models: [
          { id: "auto",      name: "ModelSaar Auto",      reasoning: false, input: ["text"], contextWindow: 128000, maxTokens: 32000,
            cost: { input: 0, output: 0, cacheRead: 0, cacheWrite: 0 } },
          { id: "auto-code", name: "ModelSaar Auto Code", reasoning: false, input: ["text"], contextWindow: 128000, maxTokens: 32000,
            cost: { input: 0, output: 0, cacheRead: 0, cacheWrite: 0 } },
        ],
      },
    },
  },
}
```

### API protocol — Verified
**Default for a custom `baseUrl` provider: `openai-completions` (Chat Completions)**; selectable per provider via `api` (`openai-responses`, `anthropic-messages`, etc.). "Proxy-style OpenAI-compatible routes skip native OpenAI-only request shaping" and omit `service_tier`, `store`, and prompt-cache hints. Custom `openai-completions` models with `reasoning: true` send `reasoning_effort` when thinking is enabled. Anthropic adapter appends `/v1` itself (Synthetic example omits `/v1` for `anthropic-messages`).

### Tool calling — Partially verified
- Tools are sent natively; per-model `compat.supportsTools: true` and `toolSchemaProfile`/`unsupportedToolSchemaKeywords` exist to sanitise JSON Schema for llama.cpp-class servers (Verified, provider-examples). Streaming is used (300 s first-response budget for local endpoints; `supportsUsageInStreaming` compat key). **Unverified:** use of `tool_choice`, `parallel_tool_calls`, `strict` — not stated in fetched docs.

### Session identifiers — Verified (reference/prompt-caching.md)
- OpenClaw sends **`prompt_cache_key`** on Chat Completions and Responses requests; key = explicit Gateway key, else **session ID + transcript reset/compaction boundary count**. **Automatic only for `api.openai.com`**; for custom OpenAI-compatible endpoints it is sent **only if `compat.supportsPromptCacheKey: true`** is set on the model ("never auto-detected for a proxy"). No `user`, `metadata`, or session header documented. **Implication:** ModelSaar docs should instruct users to set `compat: { supportsPromptCacheKey: true }` to receive a stable per-session `prompt_cache_key` for affinity.

### Networking — Verified
`request.allowPrivateNetwork` defaults to `false`; metadata/link-local/NAT64 origins blocked unless opted in; a custom `baseUrl` trusts its exact origin. OpenClaw is normally host-installed (no Docker guidance on fetched pages) — Unverified for containers.

### Pitfalls — Verified
Omitting `api` is fine (defaults to completions); do not choose `openai-responses` unless `/v1/responses` exists; declare `models[]` or the model will not be selectable; `contextWindow`/`maxTokens` must be positive finite numbers to override catalog values; agent `models.json` `baseUrl` wins over config in merge precedence.

### V1 (current `opencode.ai/docs`) — Verified
- **Files:** project `opencode.json` (searched from cwd up to nearest git root) or global `~/.config/opencode/opencode.json`; **JSON and JSONC both accepted** (`opencode.jsonc` appears in docs examples). `OPENCODE_CONFIG` = custom file, `OPENCODE_CONFIG_DIR` = custom dir, `OPENCODE_CONFIG_CONTENT` = inline. Precedence (later wins): remote `.well-known/opencode` → global → `OPENCODE_CONFIG` → project → `.opencode` dirs → inline → managed → macOS `.mobileconfig`. Files are merged, not replaced.
- **`$schema`:** `https://opencode.ai/config.json`.
- **Top-level key: `provider`** (singular). Schema (`ProviderConfig`): `api`, `name`, `env` (string[]), `id`, `npm`, `whitelist`, `blacklist`, `options` {`apiKey`, `baseURL`, `enterpriseUrl`, `setCacheKey` (bool, "enables promptCacheKey", default false), `timeout`, `headerTimeout`, `chunkTimeout`}, `models`. (Docs page additionally shows `options.headers`; the fetched schema lists `headers` only at model level.)
- **`npm`:** `@ai-sdk/openai-compatible` → `/v1/chat/completions`; `@ai-sdk/openai` → `/v1/responses` (per docs). Can be overridden per model with `models.<id>.provider.npm`.
- **Model fields (schema):** `id`, `name`, `family`, `release_date`, `attachment` (bool), `reasoning` (bool), `temperature` (bool), `tool_call` (bool), `interleaved` (bool | `"reasoning"`/`"reasoning_content"`/`"reasoning_text"`/string | `{field}`), `cost` {`input`, `output` required; `cache_read`, `cache_write`, `context_over_200k`}, `limit` {`context`, `output` required; `input`}, `modalities` {`input[]`, `output[]` ⊂ text/audio/image/video/pdf}, `experimental`, `status` (alpha/beta/deprecated/active), `provider` {`npm`, `api`}, `options`, `headers`, `variants`.
- **Keys:** `/connect` → "Other" → provider ID → key, stored in `~/.local/share/opencode/auth.json` ("only stores a credential"; still need the provider in `opencode.json`); or `options.apiKey` with `{env:VAR}` / `{file:path}` substitution. `/models` lists them. Default model: `"model": "provider_id/model_id"`.
- **Base URL:** every example includes `/v1` (`http://localhost:11434/v1`, `http://127.0.0.1:1234/v1`, `http://127.0.0.1:8080/v1`); @ai-sdk/openai-compatible appends `/chat/completions` to `baseURL` (AI SDK docs example `.../v1/chat/completions`). **Include `/v1`.**

No `user` field, no session header; `sessionID` appears only in telemetry.

### Pitfalls — Verified

### Env vars — Verified; **note the inconsistency between two official pages**
- Environment-variables reference: `OPENAI_API_KEY` = "OpenAI API key (`openai-api` provider), or the key for a custom OpenAI-compatible endpoint when `OPENAI_BASE_URL` is set" (sent only to that URL's exact origin; treated as OpenRouter key only if it starts with `sk-or-`); `OPENAI_BASE_URL` = "Base URL for custom endpoint (VLLM, SGLang, etc.)".

### Protocol — Verified

## 5. Ollama OpenAI compatibility (client-relevant) — Verified
Source: https://docs.ollama.com/api/openai-compatibility (undated; mentions Responses API "added in Ollama v0.13.3").
- Base URL `http://localhost:11434/v1/`; `api_key` required by SDKs but ignored (placeholder `"ollama"`). Cloud: `https://ollama.com/v1` with `OLLAMA_API_KEY`.
- Endpoints: `/v1/chat/completions`, `/v1/responses`, `/v1/completions`, `/v1/models`, `/v1/models/{model}`, `/v1/embeddings`.
- Chat completions supported fields: `model, messages, frequency_penalty, presence_penalty, response_format, seed, stop, stream, stream_options(include_usage), temperature, top_p, max_tokens, tools, reasoning_effort, reasoning.effort`. **Unsupported: `tool_choice`, `logit_bias`, `user`, `n`.** Images only base64 (no URLs). Parallel tool calls not mentioned.
- Responses: `model, input, instructions, tools, stream, temperature, top_p, max_output_tokens, reasoning.effort, think`; unsupported `previous_response_id`, `conversation`, `truncation` (stateless only).
- `/v1/models`: `created` = last modified, `owned_by` = Ollama username (default `library`). Context size cannot be set via OpenAI API (use Modelfile `PARAMETER num_ctx`); OpenClaw's `injectNumCtxForOpenAICompat` and Hermes's `ollama_num_ctx` exist for this reason.
- Implication for ModelSaar as a downstream of Ollama: strip `tool_choice`, `user`, `n` before forwarding to Ollama; ModelSaar itself should accept them from clients (Open WebUI/OpenCode don't send `tool_choice` by default anyway).

### Recommendations for ModelSaar derived from the above
1. Serve `GET /v1/models` with a complete list (Open WebUI and Hermes rely on it); Open WebUI's connection test is exactly this call with a Bearer token.
2. Accept and ignore `tool_choice`, `user`, `n`, `stream_options`; strip `tool_choice`/`user`/`n` when forwarding to Ollama.
3. Conversation affinity inputs, in priority order: `X-OpenWebUI-Chat-Id` header (Open WebUI), configured header from Hermes `session_affinity_header`, `prompt_cache_key` body field (OpenClaw with `compat.supportsPromptCacheKey`, possibly OpenCode), then a hash of the system prompt + first user message as fallback.
4. Document for each client: `/v1` must be in the URL; Open WebUI `TASK_MODEL_EXTERNAL=auto-fast`; OpenClaw `compat.supportsPromptCacheKey: true`; OpenCode V1 vs V2 schema (never mix); Hermes per-provider `key_env`.
