Extending ModelSaar

Rendered from docs/extending.md at commit 6fe85ca1995d. The repository file is authoritative.

See catalogue.md for adding deployments, catalogue entries and adapters.

Aliases

aliases:
  auto-reasoning:
    profile: quality
    require_tags: [reasoning]
    description: "deployments tagged reasoning"
  auto-small:
    profile: fast
    deployments: ["ollama/gemma4:e4b", "ollama/granite4.2:3b"]

Alias names must start with auto. An alias is advertised only when at least one usable deployment satisfies its constraints; its /v1/models contract reports the minimum context and whether tools, vision and json_schema are supported by every member (supported), some (partial) or none.

Profiles

routing.profiles.{quality,balanced,fast} hold the weights quality, latency, residency, overhead. routing.switching_penalty controls session hysteresis.

Per-request hints

Clients may add a modelsaar object to the request body (never forwarded to backends):

{"model": "auto", "messages": [...], "modelsaar": {"session": "run-42", "profile": "fast"}}

Optional classifier

routing:
  classifier:
    enabled: true
    backend: ollama
    model: "gemma4:e4b"       # a small local model that honours response_format
    timeout_s: 2.0
    only_when_ambiguous: true

Its calls, timeouts and failures are visible in /admin/status → classifier. If it does not improve routing in modelsaar eval, leave it disabled: the deterministic path is the simple mode.
